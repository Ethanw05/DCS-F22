# UI-01 — command and input lifecycle

The AFCS internal range is 11600–11626; lights are 11905–11912. Flight-owned
physical controls reserve 11700–11729. Device-scoped numeric transactions use
11800. Saved light bindings 10505–10512 remain light-only aliases. Unambiguous
legacy AFCS commands retain translation; ambiguous direct AFCS bindings in that
eight-ID range must use the existing dedicated cockpit AP bindings instead.
No saved input files are rewritten.

Light commands drive the existing cockpit switches. White, anti-collision and
navigation shortcuts select the existing coupled switch positions; they do not
create independent circuits. Their exterior optical effect remains a DCS check.
MFD page/view/focus/role/power changes release the original held command owner;
the held press remains suppressed until released. The radar owner supplies final
A/A and A/G axis admission through Sensor_Control/Radar_Focus. Global ACM stays
with that owner and is not changed here.

Evidence: Brower (2001), §32.3.7 establishes flexible integrated display roles;
the installed ED Hornet guide (24 March 2024), p47 supplies the explicit selection
analogue. The mod's switch/ID mapping is an interface policy, not recovered F-22
software. Actual Lua adapter/lifecycle regressions and the built DLL callback
test exercise routing. They do not establish native bezel optics or light beams.

NAV cage11840 is device-scoped to HUD_FLIGHT_DATA; AFCS loss acknowledgement is11626. Mark/time11810–11822 belong to NAV_SYSTEM, with11830 selecting its steering source. These device namespaces are separate from physical117xx and exterior119xx controls.

Waypoint/EW isolation: NAV undo/designate/undesignate retain10840–10842. Direct flare/chaff/ECM now use11114–11116, including both input profiles and DEF ECM. Device IDs alone did not isolate broadcast listeners: waypoint designate10841 could execute chaff, undo10840 could dispense flare, and undesignate10842 could toggle ECM. The actual NAV/AG/EW owners now pass raw and encoded broadcast regressions; the old EW source reproduces accidental chaff. Default combinations and existing saved input files are preserved.

AP mode options are toggles. A second selection releases BALT/RALT/V/S pitch control or HSEL/NAV lateral control while retaining a separately selected axis. ATTH stays selected while either attitude axis remains and releases only those remaining attitude holds; CAS/Mach A/T retain their existing toggle behavior. Deselect bypasses engagement eligibility gates, clears the relevant limiter/integrator/override state and cannot resume from continuing NAV data. Global AP/AT OFF clears both axes and A/T. The UFC waits for the native `F22_AP_OFF_SEQUENCE` acknowledgement and all released states before saying AP / AT OFF; a missing response reports AP OFF NOT CONFIRMED after1s. This timeout is an interface policy. Native controller and actual DLL callbacks exercise repeat selection, independent axes, lost inputs, global release and acknowledgement; the old installed DLL fails the new repeated-NAV release test. DCS flight verification remains open.

The UFC now withdraws a previous AP / AT OFF confirmation when any native mode, A/T or override becomes active through another input owner. Keyboard/HOTAS engagement cannot leave the historical OFF acknowledgement over the current selected-mode labels. Restoring an inactive state does not revive that old acknowledgement. Actual ICP regressions cover external NAV, heading, altitude and A/T activation.
