# SEN-08 — Countermeasure control lifecycle

Implemented 2026-10-27 on `codex/weapons-ew-overhaul`; offline verification only.

`EW_System` is the sole dispenser owner. Combat/HOTAS forwards commands without a second sequencer. The three existing banks and saved HOTAS IDs remain. EDIT changes a draft; SAVE validates it; CANCEL or changing edit bank discards an unsaved draft. NORMAL and DIRECT selections are independent. Existing CMS-up executes NORMAL, CMS-left DIRECT, CMS-push bank 3. Each run/event captures immutable committed settings. CYCLES includes the first cycle; legacy REPETITIONS parameter names retain that meaning.

MAN dispenses on a pilot action. SEMI snapshots a neutral event and waits for one-event consent. AUTO requires explicit authorization and a new neutral event. No operational threat-to-program selection or effectiveness algorithm is supplied. CMS-right revokes and stops; CM STOP stops the current sequence. Restoration never resumes an interrupted run or replays an event.

OFF/STBY/ON, test, readiness, inventory validity, request, observed start, completion, partial depletion, empty, fault, stop and unresolved effects are separate. Cartridge calls use the native count argument. Completion requires observed decrements; an API return is insufficient. Unresolved effects quarantine another run until reconciliation/refill. Direct single-cartridge controls cancel programmed work and share MAIN_POWER; no independent emergency supply is claimed. CM counts remain available if the optional ECM API fails.

Commands on EW_SYSTEM 20: 10910–10914 edit fields; 11100 normal, 11101 direct, 11102 bank 3; 11103 SAVE, 11104 CANCEL, 11105 NORMAL bank, 11106 DIRECT bank; 11107 mode, 11108 system, 11109 test, 11110 neutral test event, 11111 authorize, 11112 revoke, 11113 stop. New bindings have no default key combinations. DEF preserves MENU 13, uses 8 SAVE/9 CANCEL/10 NORMAL/11 DIRECT/12 MODE/16 STOP/17 CM PWR; self-test has a separate binding.

Estimates retained/selected: three banks, inherited demonstration presets/limits, flat schema, one-second game test, 0.8-second native-effect timeout, ten-cartridge LOW threshold, explicit rather than default AUTO authorization. These are mod policies, not F-22 procedures or defensive recipes. Saved programs persist across supply/refill; a new mission restores defaults.

Verification: `test_ew_programs.py`, `test_ew_controls.py`, `test_ew_backend_lifecycle.py` and actual MFD/mouse/startup regressions exercise normal, invalid draft, immutable running settings, partial/empty inventory, busy/retrigger, stop, consent, native failure, delayed effects, refill, power and reset. Actual Lua/font DEF preview inspected. Lua work is bounded to three banks, eight total cycles, one native cycle per callback and one unresolved effect. Tables allocate only within those declared bounds; runtime GC cost remains unmeasured. DCS callback timing and actual dispenser effects still require coordinated flight acceptance.

Binding descriptions now name NORMAL, DIRECT, bank3 and active consent/revoke behavior; old command IDs, up/down values and default combinations are unchanged. The former Reserved descriptions no longer imply that consent is inactive.

Supply follow-up: CM readiness/direct singles now use the coherent electrical consumer from SEN-07. Owned-frame loss or physical-generation change revokes active/awaiting/authorized work, while invalid or restored supply cannot replay a held unavailable press. Reset clears only owned outputs and preserves the physical producer's input handles. Neutral scripted events remain the declared SEMI/AUTO contract; no warning-to-program recipe was added. Self-test starts at the input's current World time, including before a scheduled update; invalid model time withdraws timed-program readiness with CLOCK_VALID0. Existing saved banks/refill semantics remain. Actual-owner failure/recovery cases are in `test_defensive_lifecycle.py`.
