# SEN-09 — Station missions and release transactions

Implemented transaction changes 2026-10-27; native DCS acceptance remains separate.

A release request captures station, store key/generation, count, launch sequence, time and immutable program/mission. Only matching armed native launch identity advances it; a count decrease alone never acknowledges delivery. Counts reconcile a previous native launch or cancelled request before the station may be reused. Jettison cancels consent before dispatch. The native payload hook forwards unarmed guided-store jettison without target-transfer permission and excludes it from launch records. Its installation no longer depends on radar fire-control enable.

The project enum names weapon jettison 82 as `PiCommandSelecterUplaneJettisonWeapons`; the old missing `PlaneJettisonWeapons` key was nil, while the cockpit WEP JET dispatched fuel-tank jettison 178. The receiver now resolves the existing 82 alias and routes the cockpit action to weapon jettison. Exact host jettison station coverage remains unflown; no synthetic inventory or mass removal is added.

Captured PP-like station missions are independent of live TOO designation. A live change requires new consent only where that live assignment is used. Four PP slots per station are a mod estimate. Capture preserves source/sequence/time; slot selection is deliberate, an empty PP slot is invalid, and saved missions survive service but require reassignment to a replacement weapon. DATA → COORD shows local game-world N/E/elevation in metres, explicitly not latitude/longitude. Actual supported fuze remains STORE DEFAULT; unsupported fuze programming is not advertised.

SIM command11120 on WEAPON_SYSTEM4 cancels consent in the input call and inhibits native arm, gun, IR and A/G release. No synthetic launch or inventory debit is generated. Weapon registration and IDs are preserved. The common profile marks experimental AIM-260/MAKO equipment unavailable when additional_weapons is disabled; indication and native release gates agree.

Station generations advance on observed replacement/refill or qualified service. Installed Hornet `Computers/SMS/sms_commands.lua` explicitly declares WeaponRearmFirstStep, WeaponRearmComplete and UnlimitedWeaponStationRestore. Those events cancel held consent, cage/reinitialize seekers and invalidate old target/guidance readiness even if type/count did not change. Structural repair is not treated as rearm. Unsampled replacements without a host event cannot be proven: F22_SMS_STORE_GENERATION_VALID stays0. Native alignment/health is not replaced with an invented Hornet timer.

Shared numeric-entry contract: unchanged `Entry_Transaction.lua` from the navigation owner, STORES lane, device command11800 token. REQUEST/ACTIVE/COMMAND/VALUE are checked before application; command10979 plus matching buffer must actually commit. ACK_VALUE contains achieved value, RESULT1 accepted/2 rejected, ACK_REQUEST publishes last. Direct10979 remains compatible. Duplicate, cancelled, mismatched and stale tokens cannot apply another draft. Integration must include navigation's UFC sender.

Evidence read: Brower (2001) chapter32 p10 SMS/jettison; installed ED Hornet guide, 24 March 2024, pp330–334, station-specific missions, alignment/health/SIM distinctions; ED Viper guide, 16 August 2026, pp366–367 and619–623, inventory, retained profiles and release-program comparison. Detailed controls, four-slot memory and timeouts are selected game substitutes. No new real guided-weapon trajectory algorithm or fuze interface is inferred.

Verification: model and actual-owner cases in `test_weapon_transactions.py`, `test_overhaul_release_contract.py`, `test_overhaul_guidance_cache.py`, `test_overhaul_stores.py`, `test_overhaul_stores_actuators.py`, common UFC/mouse tests and the native seeker adapter. Native fixtures cover unarmed jettison, real launch identity, exposure loss/staleness, same-type generation change and held-release recovery. These validate adapters/mocked effects, not a flown DCS release. Host event payload station granularity is unqualified, so service conservatively invalidates all eleven stations.

Coding exceptions: existing dense AG_Stores functions and long Weapon_System handle_command/update remain focused legacy code; new helpers separate service, correlated commit and cancellation. Work is bounded to11 stations,4 missions/station,16 launch records and one pending release. Private native ABI/lifetime guards are retained; no new offsets or allocators were added. Quantitative native/Lua decision coverage and DCS GC timing are unavailable in this environment.

Physical-provider follow-up: `Weapon_Physical_State.lua` consumes flight commit `dd11555` and its `docs/vehicle-state-contract.md` without integrating a second physical model. After the `EFM_POWER_OWNER` latch, valid/generation/stamp and clock-kind are checked before/after the payload. Clock-kind1 uses `F22_AP_CLOCK`, never World model time. The 0.25-second freshness bound and 0.05-second future tolerance are adapter estimates. Missing, nonfinite, torn, stale or invalid owned frames withdraw authority; the older-DLL fallback cannot return after the latch.

Bay/gun drive uses `EFM_UTILITY_AVAILABLE` (the provider's estimated System2/ground-transfer mapping), independently of flight-control `EFM_ACTUATOR_AVAILABLE`. `EFM_MISSION_POWER_AVAILABLE` gates native arm, release consent/effects, seeker exposure, gun drive and corresponding SHOOT advice. APU-only MAIN_POWER still permits low-load Stores editing and qualified ground bay motion. Utility is not asserted to power every store's ejector: an already-clear bay retains its achieved clearance; gun drive still requires utility. Conditioned air is not interpreted as thermal, seeker or radar-array health.

`F22_SMS_PHYSICAL_OWNER/VALID/GENERATION/STAMP` and `F22_SMS_MISSION_POWER` expose consumer qualification; generation/stamp retain the last accepted sample when VALID0. Physical generation changes cancel consent, cage the seeker and invalidate cached guidance. The IR instance token changes for either station-store or physical generation changes and withdraws on finite-token exhaustion. Provider recovery never replays cancelled release/gun consent. The native exposure timestamp retains its separate World-clock contract.
