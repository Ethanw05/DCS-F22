# UI-04 — references and fault recall

All four displays have START, TAXI, TAKEOFF, LANDING and SHUTDOWN reference views,
plus a stable fault catalogue/recall and selected fault reference. Each has MENU
return; fault detail returns to its list. The labels and actions use the common
bezel definition. ACK affects attention and never runs a repair action.

These are labelled simulation workflow references, not recovered F-22 checklists.
Achieved mass, tail angles, fuel and gear are read only from valid provider fields;
unavailable inputs display `--`. The pages do not automatically complete unsensed
items. No Hornet takeoff-trim angle is imported. The landing reference retains
the historical 12-degree approach centre with the calibration limitation recorded
in the selected profile.

Basis: Brower (2001), §§32.3.7/32.4 describes flexible display and recovery roles;
ED Hornet guide (24 March 2024), p80 is the checklist/weight/stabilator analogue.
Generic references are explicit mod procedures. Actual native-element graphs
are checked on all four panels for names, parents, view routing and bounds;
read-only/invalid-provider tests pass. Native cockpit masking, optical fit and
VR require installation qualification and are not proved by graph checks.

START now includes independent left/right engine status and control availability
from `Engine_Status.lua`, with purge/reset instructions and UNKNOWN on invalid
or stale physical feedback. The owner consumer and four-panel reference checks
pass. Actual Lua stroke-font previews of RUN, protection/recovery and UNKNOWN
states were inspected for spacing; these are synthetic-value previews, not
native DCS captures. Existing engine gauges and MENU routing are preserved.
