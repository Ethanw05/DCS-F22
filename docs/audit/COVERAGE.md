# Source-review coverage and limits

Baseline: [`9c5d03ee822323591dbf259d09b5022ced3e3d4f`](https://github.com/Ethanw05/DCS-F22/tree/9c5d03ee822323591dbf259d09b5022ced3e3d4f); 24 October 2026. Source links below are pinned to that baseline. Documentation changes do not alter the reviewed aircraft code.

## Inventory and methods

The inventory contains **132 tracked source/configuration files, 46,267 lines**: Lua/SDEF, C++/headers, JSON, workflow YAML and CMake files. All **117 Lua/SDEF** files passed Lua **5.1.5** syntax checking (only a leading UTF-8 BOM was stripped for parsing). There are **38 display page scripts**, all constructed under minimal substitutes for common DCS drawing helpers. Their checked controller parameter indices were in bounds and no repeated insertion of the same object was detected. This is not a DCS rendering test.

The central EFM and active system flows received semantic/state review. Repeated declarative pages and asset descriptors were reviewed through structure, comparisons and references. This is a full **file-coverage source assessment**, not a claim of branch-complete execution or independent verification of every undocumented DCS field. The ABI headers were inspected as contracts, rather than treated as aircraft algorithms to change.

Seven active Lua devices were loaded with synthetic host functions; selected power, trigger, hydraulic and brake paths were exercised. Extracted unchanged C++ callbacks used actual baseline state/helpers with a no-op cockpit bridge. They reproduced selected continuity, trim, repair/reset and event results. Earlier fuel and actuator experiments remain documented against unchanged code. Temporary analysis programs are outside this repository; no audit tools are added.

## What was not validated

- No installed Windows DCS runtime, full Windows DLL build, native guided engagement, clean FC-disabled boot, multiplayer/track replay, VR or rendered cockpit validation.
- No access to proprietary inherited F-15C avionics source, which supplies behavior absent from this tree.
- Compiled EDMs, DLL binaries, textures, audio and mission archives were inventoried as assets, not reverse engineered or flight-tested. No complete original 3D authoring project was located.
- No real aircraft, production F119 deck, complete aerodynamic database, operational software tape or authenticated complete HUD manual was obtained.

License/attribution and existing project documentation were also considered for distribution and provenance; they are not counted as aircraft source files below. A file mapped to a review without a defect means the checked scope produced no specific confirmed defect, not that the file is proven correct.
