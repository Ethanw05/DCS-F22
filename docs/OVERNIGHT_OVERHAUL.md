# Experimental systems overhaul — 24 October 2026

This pass follows the experimental EFM replacement at `3256d6e71bd55b342095da6a128a40b9b8c94f16`. It replaces all seven active cockpit-system devices, adds an original NAV HUD, connects supplies to physics, and fixes indicator/registration defects. **It is a test build, not a verified production F-22 simulation or a claim that every bug is fixed.** No CFD, protected-module decompilation or third-party cockpit reuse was performed. F-15 combat avionics remain required.

The [historical audit](audit/README.md) concerns `9c5d03ee...`, not the code shipped here. The earlier [flight-model ledger](FLIGHT_MODEL.md) still describes its aerodynamic/control/engine assumptions. The matrix below records this implementation pass: source review, applicable evidence, change, verification and remaining limits. A reference's existence is not treated as access to its full contents.

The subsequent [final system review](FINAL_SYSTEM_REVIEW.md) records additional code → evidence → change → verification steps: historical approach/AR configuration corrections, explicit planned-failure ownership, cold-start hydraulic recovery, APU/GPU distinction, cannon-toggle restoration, independent warning edges, held antenna controls and a loadout-ID correction. ## What the checks establish

Local Release and sanitizer builds exercise equations, conservation, callback contracts and selected rigid-body scenarios. Lua 5.1 tests cover state transitions, shared-device ownership, registration and indicator construction. These are regression checks for concrete changes, not a new generic audit framework. CI repeats the portable checks and builds the actual Windows DLL/overlay.

Neither successful compilation nor picture similarity establishes aircraft fidelity. [TEST_BUILD.md](TEST_BUILD.md) lists the simulator tests required before accepting the branch. The remaining limits above are work still needed, not features quietly supplied by a paper or by the overnight rewrite.
